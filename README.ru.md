# Baidu CarLife on Android Box

**ЭТА СБОРКА ЕЩЁ НЕ ТЕСТИРОВАЛАСЬ С АВТОМОБИЛЬНЫМ ГУ.** Это предварительный релиз для тестирования; прежние результаты Honda не являются приёмкой этой сборки.

**Carlife_on_box** добавляет в Android-бокс нативный backend Baidu CarLife: бокс передаёт собственный Android launcher и приложения на CarLife-магнитолу по USB и получает касания и команды навигации по протоколу CarLife.

[English — основная версия](README.md) · **Русский**

Это проект с исходниками для разработчиков прошивок и владельцев устройств. Рабочая реализация проверялась на Carlinkit TBox / SM6350 с Android 15 и Honda CarLife. Это **не универсальный APK и не прошивка для любого бокса**: загрузочная цепочка, USB, права на захват дисплея и ввод, а также подписи OEM-приложений различаются.

## Что работает на проверенном стенде

- Видео и ввод через прямой CarLife USB. Android Auto, Mac и ADB-туннель не участвуют в передаче изображения и касаний.
- Настоящий launcher Android, приложения, экранная клавиатура, «Домой» и «Назад».
- Зеркалирование дисплея в EGL / MediaCodec H.264, SPS/PPS + IDR, повтор статического кадра и временные метки энкодера.
- Общая геометрия видео и ввода, асинхронная обработка касаний, ограниченные очереди, барьер поколений RESET, владение источником видео и защита OEM CSD.
- Ранний выбор backend до захвата USB штатным projection-процессом; сохранённый выбор Android Auto / CarPlay / Baidu CarLife.
- Автозапуск и повторное соединение в проверенном runtime; холодный старт с заранее готовым ГУ.
- Восстановление запуска сотовой подсистемы и штатного плавающего управления на эталонном боксе.

При первой системной установке по умолчанию выбирается **Baidu CarLife**. Последующий выбор владельца сохраняется при перезагрузке.

## Текущее состояние

| Часть | Статус |
| --- | --- |
| Нативный runtime | Прежний baseline проверен на боксе и Honda; этот предварительный релиз проверен только с Mac HU |
| Полная OTA с системной интеграцией | Собрана и проверена офлайн; **не установлена, её загрузка не проверена** |
| Другие боксы | Нужны профиль устройства и аппаратная проверка |
| Аудио | USB MEDIA/TTS/VR, передача микрофонного сигнала в приложение и синтетический двусторонний звук проверены на Mac; приёмка этой сборки с автомобильным ГУ впереди |
| Native-сервисы | Звук звонков интегрирован через USB без зависимости от Bluetooth. Физический микрофон ГУ, кнопка руля, приборка и настоящие SIM/VoIP-звонки ещё требуют приёмки; [текущий статус](docs/ru/CARLIFE_SERVICES_STATUS.md) |
| Проверка телефона | Кандидат с v2 checksum прошёл офлайн-тесты; legacy RSA и шифрование media пока не поддержаны |
| Мультитач Honda | Форматы пакетов поддержаны; независимые координаты второго пальца в проверенном режиме не получены |
| Переключение кнопкой RESET | Проверены событие и диалог CarPlay; реальное переключение не проверено, цикла из трёх режимов нет |
| SELinux enforcing | Не проверен; тестовая прошивка уже была permissive |
| Задержка | Ограниченная AU-очередь и адаптация битрейта реализованы; итоговый выигрыш задержки на ГУ ещё не измерен |

Репозиторий содержит исходники, сборку и тесты. Пакет включает OEM overlay для проверенной прошивки; эти сторонние бинарники отделены от исходников Apache-2.0. Полная OTA и ключи подписи не публикуются. Успешная сборка JAR не доказывает совместимость с другим боксом или ГУ.

[Текущее состояние сервисов](docs/ru/CARLIFE_SERVICES_STATUS.md) отделяет реализацию звука/голоса/навигации/звонков по USB от проверки на боксе и приёмки ГУ. [История r6/mic-test4](docs/ru/NATIVE_CANDIDATE.md) и [разбор HeadSwap](docs/ru/HEADSWAP_LESSONS.md) сохраняют прежние результаты.

## С чего начать

Текущий [предварительный релиз](<https://github.com/SadykovIV/Carlife_on_box/releases/tag/v2026.10.16-usb-call-lab2>) содержит **`Carlife_on_box-TBox-Ultra-2026.10.16-usb-call-lab2.zip`**: один файл Magisk для первой установки и обновления совместимого TBox Ultra, включая OEM-выбор протокола и разрешения/FPS. При чистой установке выбраны Baidu CarLife и **По запросу ГУ**; обновление сохраняет выбор. Откат включён непосредственно на устройстве. См. [краткую инструкцию](docs/ru/INSTALL_RELEASE.md) и [подробное описание установщика](docs/ru/MAGISK_INSTALLER.md). Чистая установка на втором физическом боксе пока не проверена.

В сборке подключён к рабочей сессии USB-тракт звука звонков, обработаны mute/unmute и возврат музыки, убраны повторы команды статуса музыки на каждом PCM-пакете. **56 наборов JVM-тестов и 133 host-теста прошли.** На Mac проверены синтетический двусторонний звук, native RESET и переподключение сессии при активном аудиотракте. Это локальные тесты с генерируемым сигналом, не настоящие SIM/VoIP-звонки и не проверка автомобильного микрофона.

Прежние [r6](https://github.com/SadykovIV/Carlife_on_box/releases/tag/v2026.10.15-r6) и [r7](https://github.com/SadykovIV/Carlife_on_box/releases/tag/v2026.10.15-r7) сохранены как исторические релизы; их отдельные ZIP к текущему объединённому пакету не относятся. [Параметры видео](docs/ru/VIDEO_SETTINGS.md).

1. [Сборка Android MD](docs/ru/BUILD_MD.md) — общий код и native USB overlay, JVM-тесты и DEX JAR.
2. [Сборка runtime и системного overlay](docs/ru/BUILD_RUNTIME.md) — observer, selector и адресная интеграция SM6350.
3. [Перенос на другой Android-бокс](docs/ru/PORTING.md) — ранний запуск, USB, видео, ввод, права и выбор режима.
4. [HU-стенд на Mac/Linux](docs/ru/HU_LAB.md) — USB, отладочный TCP и воспроизведение пакетов.
5. [Состояние сервисов](docs/ru/CARLIFE_SERVICES_STATUS.md) — звук, ассистент, навигация и звонки; реализация и границы приёмки.
6. [Результаты проверок](docs/ru/STATUS.md) — подтверждённые факты и незакрытые проверки.

Базовые проверки без устройства (Python 3.11+ и компилятор C):

```sh
python3 scripts/test_host.py --stdlib-only
python3 -m unittest discover -s tests -p 'test_boot_native_*.py'
python3 -m unittest discover -s tools/boot_native/selector/tests -p 'test_*.py'
python3 -m unittest integration.sm6350.test_system_integration
```

Медиатестам и GUI нужны зависимости из `requirements-hu.txt`. SDK/JDK не включены; команды сборки и необходимые входные файлы указаны в инструкциях.

## Как устроено

Android display → зеркало / EGL → MediaCodec H.264 → CarLife MD → прямой USB → ГУ. В обратную сторону CarLife-пакеты превращаются в Android input events.

ГУ инициирует Android Open Accessory. Контроллер бокса управляет USB gadget, ждёт реальных событий ядра и запускает MD. Сохранённый выбор и ранний dispatcher обеспечивают одного владельца USB. Запуск AA с последующим поздним перехватом через `service.sh` не является целевой схемой.

| Каталог | Назначение |
| --- | --- |
| `android-md` | Общий протокол, видео, геометрия, ввод и тесты |
| `tools/boot_native/md` | Нативный USB overlay MD |
| `tools/boot_native/runtime` | Контроллер SM6350 и resolver версий |
| `tools/boot_native/observer` | Наблюдатель событий USB ядра |
| `tools/boot_native/selector` | Сохранение режима, privileged service, код интеграции OEM UI |
| `tools/boot_native/boot` | Шаблоны раннего init и dispatcher |
| `tools/magisk` | Установка через Magisk, обновление runtime и точный откат boot |
| `integration/sm6350` | Сборщик overlay точной прошивки и тесты provisioning |
| `hu_lab` | Хостовый CarLife HU, USB, протокол, декодирование, окно |
| `scripts`, `tests` | Переносимая сборка и офлайн-регрессии |

## Участие

См. [CONTRIBUTING.md](CONTRIBUTING.md). Для отчёта об устройстве нужны модель/плата, Android, идентификатор прошивки, модель ГУ, схема питания и стадия ошибки. Перед публикацией журналов удаляйте IMEI, IMSI, ICCID, серийные номера, ADB pairing и сетевые секреты.

Аппаратную приёмку отделяйте от mock/офлайн-тестов. При переносе сохраняйте исправления видео, RESET и ввода; документируйте boot hook, владение USB и откат. GPIO и configfs одного бокса нельзя автоматически переносить на другой.
