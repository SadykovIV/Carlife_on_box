## Что сделано

| Функция | Реализация | Аппаратная проверка |
| --- | --- | --- |
| Раздельные музыка/речь | Одна AudioPolicy: usages 0/1/14 → MEDIA канал 3, 48 кГц stereo PCM16; 12/16 → TTS канал 4, 16 кГц mono PCM16 | OEM routing, слышимость, атрибуты Яндекса, ducking |
| Радио и кнопки плеера | MediaController активного приложения, резерв — обычные media keys. MUSIC=1 спрашивает статус. Idle не запускает MEDIA_INIT. Радио останавливает музыку, сохраняя TTS | Реальный плеер и источник звука ГУ |
| Данные трека | Название, исполнитель, альбом, длительность, прогресс и ограниченная JPEG-обложка; подписки и повтор состояния | Отображение ГУ |
| Манёвры Яндекса | Listener уведомлений Навигатора/Карт внутри MD; явный RU/EN манёвр и расстояние; SHOW/UPDATE/HIDE | Настоящие уведомления установленной версии |
| Микрофон ГУ | PCM канала 5 → ограниченная очередь/pipe → SpeechRecognizer → поиск Android; VR-команда/кнопки | Провайдер внешнего PCM, штатные права, формат и настоящая фраза |
| Задержка видео | Неблокирующая очередь 8 элементов / 256 КиБ / 250 мс; после потери цепочки ожидание нового IDR+SPS/PPS. Один recovery AU до 512 КиБ допускается отдельно | Физическая задержка и декодер ГУ |
| Битрейт/FPS | Адаптация 1–4 Мбит/с по общему writer; EGL pacing; DONE после применения конкретного запроса | Динамические параметры кодека и ГУ |
| Разрешение | `720p`, `auto` по запросу ГУ с capability fallback, явный размер; согласованные SPS/уровень/crop/DPB и геометрия ввода | Каждый новый режим |

Используются существующие USB transport и единственный writer. AA/DHU, отдельный APK, новый daemon или прошивка не нужны для проверки этого runtime. Сохраняются необходимые привилегии захвата/маршрутизации/ввода. По умолчанию builder оставляет audio off / services off / 720p; кандидат включает функции явно.

`--audio-source split` разделяет звук, `remote-submix` сохраняет смешанный вариант. Ошибка split логируется и не останавливает видео/ввод; второй captor скрыто не запускается. Общий владелец AudioPolicy и синхронное освобождение предотвращают пересечение источников.

## Ошибки, найденные повторной проверкой

- Переключение музыки на радио сбрасывало сведения об активной речи до нового snapshot и обрывало TTS. Теперь речь сохраняется до свежего состояния.
- Завершение старого TTS-пакета могло поставить NAVI-статус в новую сессию. Проверка epoch и обновление выполняются атомарно.
- Поздний начальный status мог отправить NAVI/VR=0 во время подсказки/распознавания. Writer собирает его из актуального состояния перед записью.
- При быстрых FPS 30→15→30 последний запрос мог получить преждевременный ACK. Теперь конкретный объект запроса проходит до EGL перед DONE.
- Старые счётчики перегрузки очереди могли снизить bitrate после RESET. Новый регулятор начинает с текущих счётчиков.
- При раннем USB-подключении сервисы Android могли ещё отсутствовать. Повторяются только неудавшиеся регистрации, асинхронно; успешные listener не дублируются, отказ прав/API не скрывается повторами. Диагностика новых сервисов идёт в существующий ограниченный журнал.

RESET, source lease, CSD guard и мультитач-декодеры сохранены и проверяются регрессиями. Провал теста с живым worker больше не оставляет builder висеть без журнала.

## Чего результат не доказывает

Уведомления Яндекса не гарантируют полный маршрут: неизвестный текст не превращается в выдуманный манёвр; дорога, полная дистанция, ETA и произвольные иконки не угадываются. Точный профиль Desay G6S не удерживает NAVI активным только из-за маршрута, но TTS по-прежнему его включает.

Голос — push-to-talk распознавание/поиск, не подмена микрофона любой клавиатуры или ассистента. Ответы с usage 16 идут в TTS. Звонки, Bluetooth mic bridge и эхоподавление не заявлены. Нужен установленный распознаватель, принимающий внешний PCM; права Android не обходятся.

Реализованы AVC levels до 4.2: для 2240×976 есть независимые SPS; 2560×1440 превышает этот бюджет. FPS ограничен начальным потолком выбранного режима. DPI Android не меняется. OEM CSD-исключение только прежнее 10→31; для старших уровней нужны совпадающие исходные CSD.

V2 checksum сохранён; legacy RSA/media encryption не реализованы. Мультитач зависит от фактически переданных координат ГУ. Загрузка 50–60 секунд не измерена заново и не объявлена исправленной; метки стадий сохранены, новых sleep и другого видеотракта нет.

## Сборка и повторение

Точные команды — в [основной инструкции](../NATIVE_CANDIDATE.md#reproduce). API 35, JDK 17, обычный `scripts/build_md.py`, затем `scripts/build_runtime.py` с:

```text
--audio-source split --native-services on --video-mode 720p
```

Первый аудиокандидат сохраняет проверенную геометрию `720p`. Для отдельного опыта с размерами — `--video-mode auto` или явный размер; приёмка нового разрешения не требуется для обычного звука. Необязательный аргумент MD `--voice-recognizer package/.Service` выбирает провайдера; иначе используется настроенный Android default.

Builder меняет только staging. Для текущего бокса сохраняется версия runtime по умолчанию: resolver, selector и boot hook менять не требуется. Кандидат установлен через [обновление runtime в Magisk](MAGISK_RUNTIME_UPDATE.md), первая рабочая версия сохранена для отката. Сборка с отдельной custom version остаётся проверкой упаковки, а не установленной конфигурацией. Это не команда записи boot. Существующие selector и загрузочная интеграция сохранены.

Подтверждение владельца для r3 полезно, но не заменяет эту проверку финальной сборки. Затем проверить метаданные/reconnect и реальное уведомление/VR-фразу. Физическую задержку и стадии загрузки измерять отдельно; готовность всего набора не является условием обычного звука.

Первичные источники и точные ограничения — в [English](../NATIVE_CANDIDATE.md). Код HeadSwap не копировался; используется его опыт совместимости. Две NAVI-схемы проверены независимым protobuf-декодером; уведомления в тестах синтетические и так обозначены.
