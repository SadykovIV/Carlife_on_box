# Установка, обновление и откат ver0.2

**Предварительный релиз: именно этот ZIP ещё не устанавливался и не проверялся на устройстве.** Он содержит проверенный baseline C10 и исправление очистки C11. На боксе владельца для автомобильных тестов остаётся C10.

[English](../INSTALL_RELEASE.md) · [Подробная инструкция](MAGISK_INSTALLER.md) · [Состояние функций](CARLIFE_SERVICES_STATUS.md)

**Один файл: `Carlife_on_box-TBox-Ultra-2026.10.17-v0.2.zip`.** Скачайте его из [предварительного релиза v2026.10.17](https://github.com/SadykovIV/Carlife_on_box/releases/tag/v2026.10.17).

SHA256: `bc25a436996a52a43932d984e7a4ffc8e04ca43d9b50a6755d5823b5bda7f6ea`.

Изменения относительно [v2026.10.16](https://github.com/SadykovIV/Carlife_on_box/releases/tag/v2026.10.16): ускорены запуск и переподключение USB; сохранённые разрешение/FPS больше не перекрываются стартовыми значениями и применяются через корректное переподключение; переработаны голосовой цикл Яндекса и предварительная подготовка захвата звука; добавлено адресное исправление исходящего звука SIM-вызова в OEM AudioTrack. C11 дополнительно ожидает завершения временных процессов в cgroup контроллера при очистке во время обновления/остановки.

Владелец принял автоматическое переподключение baseline C10 — примерно **5–7 секунд**. Предшествующий C9 прошёл холодный тест: первый закодированный кадр на **21,708 с uptime**. Неизменённый MD прошёл **57 наборов JVM-тестов**, C11 — **167 host-тестов контроллера**. Очистка C11 на устройстве ещё не проверена. Слышимость начала фраз, ответы ассистента, поведение руля и настоящие SIM/VoIP-звонки в обе стороны ждут проверки в автомобиле. Ранее 60 FPS вызывали сильные задержки на испытанной Honda и повторно не проверялись; используйте Auto или 30 FPS. Чистая установка на втором физическом TBox остаётся непроверенной.

1. Нужен совместимый **TBox Ultra 1 / SM6350 / Android 15** с работающим Magisk/root. Для первой установки — Magisk 30.7+, уже разблокированный загрузчик и существующий permissive эталонной прошивки. Установщик проверяет OEM-файлы и не меняет защиту.
2. Сверьте ZIP с checksum релиза. Обеспечьте стабильное питание и выберите файл в **Magisk → Модули → Установить из хранилища**.
3. Перезагрузитесь один раз. Один ZIP обслуживает чистую установку, прежний universal и поддерживаемую ручную интеграцию. OEM-настройки включены. При чистой установке выбраны **Baidu CarLife** и видео **По запросу ГУ**; обновление сохраняет выбор.

Только первая установка сохраняет и патчит собственный активный boot; обновления runtime его не меняют. Перепрошивать весь бокс или извлекать boot на компьютер не нужно. Для обслуживания сохраните Wi-Fi ADB или резервный экран: USB в CarLife обслуживает ГУ.

Для состояния или отмены пакета выполните в Android-терминале с root либо существующем ADB shell:

```sh
su -c '/data/adb/magisk/busybox sh /data/adb/carlife-package/control.sh status'
su -c '/data/adb/magisk/busybox sh /data/adb/carlife-package/control.sh rollback'
```

После успешного отката перезагрузитесь. **Чистая/universal:** возвращается исходный boot, управляемый CarLife удаляется. **Прежняя ручная интеграция:** возвращаются точные runtime/UI до первого объединённого ZIP; прежний CarLife и boot остаются. В обоих случаях возвращается прежнее состояние OEM overlay. Откат следует сохранённой ветке установки и **не обязательно возвращает непосредственно предыдущий релиз или C10**. Отдельный ZIP отката не нужен.

Сохраните `/data/adb/carlife-package/` и резервные копии backend. Выключение/удаление одного модуля — не полный откат. Конфликты и границы восстановления — в [подробной инструкции](MAGISK_INSTALLER.md). Прежние инструкции r6/r7 с несколькими файлами сохранены как история и к объединённому пакету не применяются.
