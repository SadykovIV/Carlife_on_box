## Поддерживаемые устройства

Поддерживаемый профиль — **TBox Ultra 1 / SM6350 (lito) / Android 15** с исследованными OEM-файлами запуска и парой APK MainAiBox/Settings. Одного названия модели недостаточно: установщик проверяет реальные файлы. Это не установщик для любого Android-бокса.

Для первой установки нужны работающий **Magisk 30.7+ / root**, уже разблокированный загрузчик и существующий permissive SELinux эталонной прошивки. Установщик не разблокирует устройство и не меняет эти настройки. Чужого boot-образа в ZIP нет: локальный `magiskboot` патчит собственный активный boot бокса. Извлекать образ на компьютер или собирать ZIP отдельно для каждого устройства не нужно.

## Установка и обновление

1. Скопируйте `Carlife_on_box-TBox-Ultra-2026.10.17-v0.2.zip` на бокс. При скачивании из релиза сверьте SHA256 с его `SHA256SUMS`.
2. Обеспечьте стабильное питание. Откройте **Magisk → Модули → Установить из хранилища**, выберите ZIP и дождитесь успеха.
3. Перезагрузите бокс один раз. В штатных настройках доступны **Android Auto / CarPlay / Baidu CarLife**, рядом — разрешение/FPS CarLife. При чистой установке выбраны **Baidu CarLife** и видео **По запросу ГУ**; обновление сохраняет выбор владельца.
4. Подключитесь к готовому CarLife ГУ. Текущие границы звука, голоса, навигации и звонков — в [состоянии функций](CARLIFE_SERVICES_STATUS.md).

При первой установке сохраняется исходный активный `boot_a` или `boot_b` и добавляется ранний запуск CarLife до захвата USB штатным projection. Также исправляется известная конфигурация serial console TBox; неизвестная UART-конфигурация сохраняется и отмечается в журнале. Полная прошивка, другие разделы и второй boot-слот не записываются.

Прежний universal получает обновление runtime без перезаписи boot. Поддерживаемая ручная интеграция также сохраняет свой boot и получает точную копию runtime/UI до объединённого пакета. Последующие обновления не заменяют первую копию. Несовместимые или незавершённые операции сохраняются с сообщением, а не удаляются ради продолжения установки.

Включённый OEM overlay добавляет выбор протокола и страницу разрешения/FPS рядом с Baidu CarLife. Исходные системные APK не перезаписываются. Допускаются только исследованные пары APK; распространение этих бинарников отделено от исходников Apache-2.0. Цикл трёх режимов кнопкой RESET пакет не добавляет.

Настройки ADB сохраняются. В CarLife USB обслуживает ГУ; для обслуживания используйте имеющийся Wi-Fi ADB или резервный экран.

## Состояние и полный откат пакета

Выполните в Android-терминале с root или существующем ADB shell:

```sh
su -c '/data/adb/magisk/busybox sh /data/adb/carlife-package/control.sh status'
su -c '/data/adb/magisk/busybox sh /data/adb/carlife-package/control.sh rollback'
```

`status` показывает сохранённую ветку и резервную копию. `rollback` выполняйте, когда нужно отменить пакет; дождитесь успеха и перезагрузитесь. Второй файл скачивать не требуется.

| Определённая установка | Что возвращает откат |
| --- | --- |
| Чистая или прежняя universal | Точный boot бокса до его первой universal-установки, включая прежний Magisk; управляемый runtime CarLife удаляется. OEM overlay возвращается к состоянию до первого объединённого ZIP либо удаляется, если тогда отсутствовал. |
| Прежняя ручная/native-интеграция | Точный runtime и OEM overlay **до первой установки объединённого ZIP**. Прежний CarLife и boot остаются; это не удаление ранее сделанного вручную изменения boot. |

Выключение или отдельное удаление модуля доставки не является полным откатом пакета. Команда выше согласованно обрабатывает runtime и overlay настроек. Это не factory reset: root и пользовательские приложения сохраняются.

Не удаляйте `/data/adb/carlife-package/` и исходные каталоги восстановления backend: `/data/adb/carlife-on-box/` для управляемого boot, `/data/adb/carlife-runtime-update/` для прежнего updater. Независимо изменённые boot/файлы вызывают сообщение о конфликте, а не перезаписываются. Обрыв записи boot может потребовать способа восстановления бокса; при первой установке необходимо стабильное питание.

## Сборка и прежние пакеты

[scripts/build_magisk_package.py](../../scripts/build_magisk_package.py) проверяет совпадение runtime, включает существующие universal/update/rollback backend и исследованный OEM overlay, выпускает один ZIP, manifest и checksum. Внутренние backend не нужно скачивать отдельно пользователю объединённого пакета. Toolchain описан в [BUILD_MD](BUILD_MD.md) и [BUILD_RUNTIME](BUILD_RUNTIME.md).

[Результаты обновления r6](MAGISK_RUNTIME_UPDATE.md) и [инструкция настроек r7](INSTALL_VIDEO_SETTINGS.md) относятся к прежним пакетам. Их результаты сохранены как история; выбор нескольких файлов из тех инструкций к текущему объединённому пакету не применяется.
