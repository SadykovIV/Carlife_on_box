# TBox Ultra 1: установка, обновление и откат через Magisk

[English — основная версия](../MAGISK_INSTALLER.md) · [Главная](../../README.ru.md)

**Один ZIP устанавливает нативный CarLife на совместимые TBox Ultra 1 / SM6350 с Android 15.** Не нужно заранее извлекать boot на компьютер и пересобирать пакет для каждого бокса. При установке модуль сам читает активный boot этого устройства, сохраняет его и добавляет ранний запуск CarLife через локальный `magiskboot`. **Чужого boot-образа в ZIP нет.**

**Статус:** установщик проверен офлайн; установка, обновление и откат на втором физическом TBox ещё требуют проверки. Принятый рабочий runtime тестового бокса и его сборки сохранены.

## Установка и обновление

1. Скопируйте `Carlife_on_box-TBox-Ultra-1-universal.zip` на бокс.
2. Откройте **Magisk → Модули → Установить из хранилища**, выберите ZIP и дождитесь успешного завершения. Во время сохранения и записи boot сохраняйте питание.
3. Один раз перезагрузите бокс и подключите его к готовому CarLife ГУ. **При первой установке по умолчанию выбран Baidu CarLife.**

Для обновления установите новый универсальный ZIP тем же способом. Установщик узнает свою прежнюю установку: обновление runtime применяется при следующей загрузке, выбранный режим и первая резервная копия boot сохраняются. **При обновлении runtime boot повторно не записывается.** Обновление должно сохранять установленные ранние точки входа; их изменение относится к новой загрузочной интеграции.

При первой установке записывается только активный boot-раздел (`boot_a` или `boot_b`, определяется автоматически). Системные разделы Android, второй слот, приложения, данные, существующие настройки AA/CarPlay и ADB остаются прежними. CarLife запускается до захвата USB штатным projection-процессом, без позднего перехвата через `service.sh`.

ZIP проверяет фактические OEM-файлы запуска, плату и версию Android поддерживаемой прошивки. Другой fingerprint или хеш исходного boot сами по себе не требуют отдельного пакета. Нужны работающий Magisk 30.7 или новее/root, уже разблокированный загрузчик и существующий SELinux permissive эталонной прошивки; установщик эти настройки не меняет. Установленный другим способом рабочий baseline сохраняется, а не принимается под управление автоматически.

В режиме CarLife USB обслуживает ГУ. Для обслуживания используйте существующее Wi-Fi ADB или резервный экран AA/CarPlay. Кнопка **Действие / Action** модуля показывает состояние. Пакет не заменяет проприетарные APK настроек/launcher, не добавляет третий пункт в их меню AA/CarPlay и не меняет RESET. Необязательная интеграция OEM UI описана в [сборке из исходников](BUILD_MD.md).

## Полный откат

В Android-терминале с root или внутри существующего ADB shell выполните:

```sh
su -c '/data/adb/magisk/busybox sh /data/adb/carlife-on-box/manager.sh rollback'
```

После сообщения о восстановлении исходного boot перезагрузите бокс. Модуль, его runtime и файлы выбора режима удаляются. **Исходный** — это точный boot данного бокса до первой установки, включая уже имевшийся Magisk. Сброса к заводским настройкам и удаления root нет.

Другой способ — **Удалить / Remove** в Magisk. Hook удаления восстанавливает boot при следующей загрузке; затем нужна ещё одна перезагрузка, чтобы загрузиться с восстановленным образом. **Выключение** модуля и перезагрузка только временно возвращают существующий штатный режим AA/CarPlay; это не полный откат.

Manager восстановления, `original.img`, индивидуальный `boot.env` и журналы остаются в `/data/adb/carlife-on-box/`, вне модуля. Если другой инструмент изменил boot после установки, откат сообщит о несовпадении и сохранит новый образ. При обрыве записи boot может потребоваться способ восстановления самого устройства.

Если boot уже записан, но Magisk не завершил регистрацию модуля, выполните сохранённую команду отката, перезагрузитесь и повторите её для очистки: hook удаления может отсутствовать. При неподходящем профиле или ошибке локального патча boot не записывается.

## Сборка ZIP

Пакет собирается один раз для поддерживаемого профиля прошивки и используется на совместимых боксах. На компьютере нужны Python 3.11+, собранные [runtime и selector](BUILD_RUNTIME.md), а также OEM-файлы `init.rc` и `sd-reverse.sh` этого профиля. **Boot целевого устройства, fingerprint, выбор слота, полный архив прошивки, проприетарные APK и ключ подписи не нужны.** `magiskboot` берётся из уже установленного Magisk; дополнительные инструменты на Android не устанавливаются.

```sh
python3 scripts/build_magisk_installer.py universal \
  --init /path/to/system/etc/init/hw/init.rc \
  --oem-script /path/to/system/bin/sd-reverse.sh \
  --runtime build/runtime/runtime/boot-native-runtime.tar \
  --runtime-manifest build/runtime/runtime/bundle-manifest.json \
  --selector-release build/runtime/selector \
  --output build/magisk-universal
```

Результат: `Carlife_on_box-TBox-Ultra-1-universal.zip`, `manifest.json` и `BUILD.json` с хешами. Для обновления повторите команду с новым runtime и новым выходным каталогом. Явно выбирайте нужный runtime: упаковка непроверенного аудиокандидата не означает приёмку звука на ГУ.

Используется штатный [жизненный цикл установщика и boot-скриптов Magisk](https://topjohnwu.github.io/Magisk/guides.html). «Универсальный» здесь означает один пакет для поддерживаемого профиля прошивки, а не для любого Android-бокса.
